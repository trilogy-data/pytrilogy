# Plan: close the ingest-vs-enriched gap

Investigation date: 2026-08-15. Evidence base: run `20260813-125008` (all four legs,
deepseek-v4-flash, sf=1, 99 queries), scored offline on the current tree (the run was
killed before its report step; stranded `_worker_*/answer_*.preql` files were staged
back for 6 ingest + 5 enriched queries), plus the ingest pipeline audit and per-query
transcript diagnosis below.

Two measurement caveats to resolve before trusting the endpoint numbers:

1. **Enriched-leg contamination.** The enriched workspace ships two answer-shaped
   files: `raw/repro.preql` (a q5-shaped all_sales query) and
   `raw/_q04_agent_rowset_union_join.preql` (a near-complete q4 answer). They pass the
   `("query", "adhoc")` skip-prefix filter in `evals/tpcds_agent/spec.py` and are
   visible to the agent. Quantify (or just remove) before attributing the full delta
   to modeling quality.
2. **Both legs lose queries to a harness defect** (duckdb worker lock, below), so the
   crashed-query sets are noise, not signal.

## Root-cause decomposition

Ranked by measured impact on the ingest leg. (a)-(c) are model gaps, (d)-(f) are not.

**(a) Topology: no sales<->returns merge, no cross-channel union model.** The single
largest lever, roughly 2.4M wasted tokens across q40/q50/q93/q25/q05 alone plus the
q17/q66 crashes and several fails. Ingest emits 1 file per table with independent
keys; the agent must hand-build `subset join` chains on (ticket|order_number, item)
and then spends 6-12 turns proving cardinality. Enriched folds each `*_returns` fact
into its `*_sales` file at the shared grain (`CR_ORDER_NUMBER: ~order_number`) and
ships `all_sales.preql` (12 partial datasources unifying 3 channels). Cross-channel
and sale+return questions are roughly a quarter of TPC-DS.

**(b) Semantics on concepts: docs, naming, derived helpers.** The wrong-answer driver
(silent result-set diffs). Concrete load-bearing examples the ingest model lacks:
unit vs extended price on `sales_price`/`ext_sales_price` (q40 burned ~290k on this
alone), `item.id` non-uniqueness (SCD), `week_seq` arithmetic, the dim `quarter` vs
calendar-quarter trap, `is_returned` true-or-NULL semantics, derived `profit`,
`line_item` count helper. Also naming inconsistency generated by prefix-stripping:
`reason.sk` vs `item.item_sk` vs `web_site.site_sk`, and role aliases that differ per
file (`store_sales` imports `date_dim as date_dim`, `catalog_sales` gets `sold_date`),
which the agent must reconcile inside a single cross-channel query (visible in its
q14 answer).

**(c) Enum/bounds noise misleads and bloats.** `detect_enum_types` runs on the full
table with no key-column or cardinality-relative gate: 122 enums (vs 28 in enriched)
including `key call_center_sk enum<bigint>[1,2,3,4,5,6]` and sf-dependent
single-value enums (`state enum['TN']`) that trigger false "this filter is a no-op"
reasoning (q01 trace; the string "enum" appears 13,870 times in the ingest-leg logs).
One past silent wrong answer already traced to this class: q16, where a
domain-covering `call_center.county` filter read as a no-op and removing it dropped
the join's null-rejection (the parser-side check was deleted in response 2026-07-20).

**(d) FK inference is NOT the problem.** Audit result: 104 edges emitted, 103 true,
1 false, 1 missed. Recall/precision 99%. The remaining defects are cheap hygiene
(§Phase 1). The false edge matters though: `web_page.wp_web_page_id` is re-bound to
`catalog_page.catalog_page_id`, so web_page loses its own business key entirely
(dead-ended q05).

**(e) Framework bugs, leg-agnostic but ingest pays more** (it writes more unusual
shapes because it lacks the pre-solved models):
- q36: naming intermediate aggregates (`auto total <- sum(x)` + `grouping()`) feeding
  rollup+window re-anchors at fact grain and fans out (94M rows). Reproduced on HEAD;
  inlined forms emit clean SQL. Enriched dodged it by luck of formulation.
- q83: 3-way chained `union join`: zero-length delimited identifier ParserException,
  `_combined_item_code` Binder error, and ORDER BY silently ignored. Both legs hit it.
- q95 (enriched): generated SQL contains `count(max(...))`, BinderException.
- q30 (ingest): 180s scoring timeout, needs a probe (planner loop vs runaway query).

**(f) Harness defects that poison measurement:**
- DuckDB worker-file lock: `IO Error: Cannot open file ..._worker_N\warehouse.duckdb:
  being used by another process`. 35 hits in ingest logs, 52 in enriched; ~0.76M
  tokens on q68 alone (semantics solved at msg 22, then 30+ retry turns); likely
  cause of most of the 13 crashed/unscoreable queries.
- Killed runs lose finished answers: candidates stage from worker dirs only at the
  per-query finalize; a killed run leaves `answer_<hash>.preql` stranded and no
  report. (This investigation recovered them by recomputing the blake2s opaque id.)
- `explore` does not show a fact's own FK columns and `file read` is disabled, forcing
  query-probe archaeology (q05, q50, q83). **Partly addressed as of 2026-08-16:** the
  JSON payload now groups imported dims by ACCESS PATH under the fact and carries a
  `join_note`, which closed the older q95 report; re-measure before re-planning this item.

## Plan

### Phase 0: make the ruler honest (harness, small)

0.1 Fix the worker DB lock: per-worker copy already exists, so the residual collision
    is scoring/CLI concurrent open. Add retry-with-backoff on `IOException: file in
    use` in the eval CLI wrapper, or open read-only where possible. Success test: zero
    `being used by another process` lines across a full 4-leg run.
0.2 Stage candidates + write partial report incrementally so a killed run still
    scores. (Recovery logic from this investigation can be folded in.)
0.3 Remove `repro.preql` and `_q04_agent_rowset_union_join.preql` from the enriched
    seeding (extend `enriched_skip_prefixes` or delete the files), then re-baseline
    the enriched leg once. This sets the true target the ingest leg is chasing.

### Phase 1: mechanical ingest fixes (no LLM, high confidence)

1.1 FK hygiene in `trilogy/ingest_helpers/fk_inference.py`:
    - carry column datatypes into `TableFKInfo` and pre-filter candidates on type
      compatibility (kills all 22 sniff errors and the false web_page edge);
    - stop offering a table's own alternate/business keys as FK sources
      (`generate_candidates` currently skips only the grain key);
    - tighten `_stem_related` (whole-token equality, not `token in short`) and make
      the table-name rule consume the whole table stem;
    - when the child column is 100% NULL, fall back to name+type match instead of
      silently dropping (`cc_closed_date_sk`, the single missed edge).
1.2 Naming consistency in `ingest_helpers/formatting.py` + role aliasing:
    - uniform `sk`/`id` for elected grain key and unique business key (the code
      already knows both);
    - global role-alias table so `*_sold_date_sk` becomes `sold_date` in every fact,
      including when a file has only one date FK.
1.3 Enum/bounds gating in `ingest_helpers/typing.py`: never on key/FK columns; require
    distinct-count small relative to row count. REVISED 2026-08-15: keep single-value
    enums (knowing the data has exactly one value is genuinely useful); the trap is not
    the domain, it is the agent concluding a whole-domain filter is droppable when the
    field is reached through a nullable join. Addressed first via 1.5 below.
1.5 (IMPLEMENTED 2026-08-15, under A/B) Explore effective-nullability rendering,
    `trilogy/scripts/explore.py`: concepts in a namespace reached through a `?`
    cross-namespace binding render with the effective `?` marker
    (`county enum<string>['Williamson County']?;`), namespace entries carry
    `join: "nullable"` (or `{"nullable": [subset]}` for mixed conformed role groups),
    and the payload carries a one-time `join_note` legend. The edge, not the leaf,
    carries the nullability (q16: `county` is non-null locally; `cs_call_center_sk` is
    the `?`). Kill-switch for control legs: `TRILOGY_EXPLORE_EFFECTIVE_NULLS=0`.
    Measured payload cost: +5.5% ingest / +5.0% enriched summed across model files
    (mostly the per-payload legend; ~1.5-2% per explore call on a large fact).
    Side finding: on the enriched model the marker renders `sale_date` nullable but
    `return_date` NOT nullable, faithfully exposing the known q78-class defect
    (return-side bindings not `?`-marked in the hand model).
    A/B RESULT (2026-08-15, q16 ingest sf=1, 10 reps/leg, deepseek-v4-flash,
    control = kill-switch on, runs repeat_q16_20260815-164641/-165916):
    pass 9/10 -> 10/10; prompt tokens mean 337k -> 218k (-35%), median 313k -> 209k;
    iterations 11.6 -> 8.8; explore calls 3.5 -> 2.4. Control logs contain zero
    markers, treatment payloads carry them (73 hits); all treatment reps kept the
    county predicate. Single-query evidence: confirm on the next full 4-leg run
    before declaring category-wide.
    Side finding from the control leg (r04 fail): apparent "pinned aggregate in
    WHERE doesn't filter". PROBED 2026-08-15, verdict NOT-A-BUG
    (bug_where_pinned_aggregate_ignored.md): the pin is honored; WHERE gates on the
    POPULATION-scope value by design (where_scope_normalization.py), and the
    population count made the predicate vacuously true. The WHERE form (233) matched
    official TPC-DS q16; the agent's inline-`?` rewrite (178) regressed a correct
    answer. Real follow-ups: (a) planner crash `select k, count(x ? pinned_agg > n)
    where <plain pred>` raises UnresolvableQueryException
    (strategy_builder.py:2039), needs a ticket; (b) sharpen the misleading
    "(like `having`)" phrase at trilogy/ai/syntax_examples.py:900 with an explicit
    population-vs-filtered scope note; (c) surface `run --scope` in agent guidance.
1.4 Deterministic descriptions: leading file comment stating grain + linked dims
    ("Fact at (item_sk, ticket_number), links: date_dim, store, customer...") and
    template per-column notes where derivable (key, business id, FK role). This fills
    the `file list` description channel that is currently boilerplate.

Validation: re-ingest, assert FK table is 104/104 with zero stderr; A/B
`repeat_query.py --category ingest --repeats 10` on q05 and q83 (naming/enum
sensitive), plus a no-op control leg per the standard protocol.

### Phase 2: topology synthesis (the big lever)

2.1 Same-grain fact merge: post-ingest pass that detects fact pairs where table B's
    elected grain columns all FK-map onto table A's grain columns (exactly the
    `*_returns` -> `*_sales` shape, and already computable from the inference output).
    Emit B's columns into A's file bound at A's grain with `~` partial bindings, plus
    a generated `auto is_returned <- <probe> is not null`.
2.2 Union model generation: when N facts share role-compatible dims and congruent
    measure names (the three sales channels), emit an `all_sales`-style union file
    with a synthetic `channel` key, plus routing comments in the member files
    ("for cross-channel questions prefer all_sales"). This is more design-heavy than
    2.1; acceptable to make it opt-in (`ingest --unions`) and TPC-DS-validated first.
2.3 If 2.2 proves too aggressive to fully automate, the fallback that still captures
    most value: generate the *routing scaffolding* only (a `_model_guide.preql`
    comment index naming every fact, its grain, and its join partners), since the
    q17/q66 crashes were routing failures, not join-syntax failures.

Validation: `repeat_query.py --repeats 10 --category ingest` on q40, q50, q93, q25
(merge) and q66, q14 (union). Target: near-enriched token cost and pass parity on
those ids. These are agent-written queries per the standing rule; no hand-authored
solutions.

### Phase 3: opt-in LLM enrichment (`ingest --enrich`)

Wire `trilogy/ai` providers into ingest as an explicit flag that: expands
abbreviations (`moy` -> `month_of_year`), writes column descriptions from name +
type + sampled values, names FK roles semantically (`ss_cdemo_sk` -> point-in-time vs
current), and proposes obvious derived concepts (`full_name`, `days_to_ship`).
Must fail loudly when the provider is unavailable (no warn-and-continue). The
hand-earned gotchas (quarter trap, week_seq arithmetic, `numeric(15,2)` pins) are not
derivable; they stay the province of curation, and that residual is the honest
long-term difference between the two legs.

### Phase 4: framework bugs (independent track, helps every leg)

File and fix, per the standard >500k-sink process:
- rollup + named intermediate aggregate fan-out (q36 repro exists against HEAD);
- 3-way chained union join parser/binder failures + silently dropped ORDER BY (q83);
- nested-aggregate codegen `count(max(...))` (q95 enriched candidate);
- q30 scoring timeout probe.

### Sequencing and measurement

Phase 0 first (cheap, unblocks honest measurement), then 1 and 4 in parallel, then 2,
then 3. After Phases 1+2: full 4-leg run, compare ingest vs the re-baselined
enriched. Success criteria: ingest within ~2 points of enriched pass rate, ingest
token total within ~15% of enriched, zero lock-related crashes. Expected recovery
from the transcript analysis: topology ~2.4M tokens plus 4-6 queries, semantics ~1M,
framework fixes ~1.1M (both legs), lock fix ~0.8M plus the 13 crashed queries.
